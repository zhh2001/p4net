# 路线图

## 关于本文档

这是一份滚动路线图，不构成承诺。同一版本内的条目按大致优先级
排列，但相对顺序会随着 issue 与权衡的清晰化而调整。任何条目
都欢迎 PR——请先在对应 issue 中讨论一下，让设计在公开场合先
完成一次，再开始编码。

## 已发布的里程碑

- **v0.1.0**（2026-05-10）—— 首个公开发布。拓扑 DSL、P4Runtime
  控制平面、BMv2 编排、交互式 CLI。详见[变更日志](changelog.md)。
- **v0.2.0**（2026-05-10）—— 控制器数据包 I/O、IPv6 主机寻址、
  非对称链路损伤、拓扑可视化、`xterm` 帮助方法。详见
  [变更日志](changelog.md)。

## v0.3.0 候选项

### PSA 架构支持

超出 v1model。需要 `p4c` 与 BMv2 带 PSA 目标编译（多数发行版的
标准包不带）。编译器封装层需要学会按架构选择对应的
`simple_switch` 变体；`P4InfoIndex` 不需要变化，因为 P4Runtime
把架构与控制器解耦。

### 运行时拓扑变更

`Network.add_host(...)`、`Network.add_link(...)` 以及对应的
`remove_*`，在网络已经运行时使用。目前 `Topology` 在 `start()`
时即冻结。底层原语（命名空间、veth 对）已经支持在线增删；编排
器的簿记只需要复用同一套代码路径。

### 异步 P4Runtime 客户端

基于 `aio-grpc` 的 `P4RuntimeClient` 变体，面向事件驱动的控制器
（例如同时订阅多台交换机 StreamChannel 的场景）。可能与现有的
线程版本并存，共用同一个 `P4InfoIndex`，而不是替换它。

### 对称基础 + 按方向追加的链路损伤

v0.2 要求每个参数要么对称要么非对称（构造期拒绝混用）。
`delay_a_to_b_extra` / `delay_b_to_a_extra` 形式允许在对称基础上
按方向叠加——例如 10ms 基础链路上叠加上行单独 50ms 抖动——
而不需要把两侧都写全。`bandwidth`、`jitter`、`loss_pct` 同样
适用。来自 phase-12 OQ #4。

### `<switch> table dump` 跨交换机的 action 参数消歧

目前 `_render_action_params` 走 dispatcher 命中的那个交换机的
索引。多交换机拓扑中，若两台交换机刚好有同名但参数位宽不同的
动作，按交换机查询本来就是对的——但早期版本里曾经有「第一台
胜出」路径，可能通过模块级帮助函数泄漏出去。把每一个帮助函数
都绑定到具体的 `P4InfoIndex`，而非取网络中的第一个。来自
phase-13 OQ #1。

## 长期搁置

- **跨多机的分布式仿真**。这是 v1.0 才会讨论的事情；不在 v0.x
  范围内。把两套 p4net 跨网络联起来需要主机间 L2 隧道与一层
  协调；当前架构对此没有任何设计。
- **拓扑可视化与运行时状态的 Web UI**。如果它真的发生，会以
  独立仓库的形式存在。保持 p4net 本身不依赖前端框架。
