## 1.x 候选项（仅追加，不破坏 API）

本页尚未为具体的 1.x 版本指定新功能。兼容性修复和新增接口遵循 API 稳定性约定。

## 2.0 候选项（可能需要破坏 API）

以下方向需要先完成设计，再确定接口和版本范围。新增独立方法或类可以保持兼容。对稳定 API 的不兼容变更须完成弃用周期，并在新的主版本中发布。

### PSA 架构支持

`Topology.add_switch()` 已有 `arch` 参数，目前只接受 `"v1model"`。`Network` 启动的是 `simple_switch_grpc`。支持 PSA 需要集成匹配的编译器和运行目标，BMv2 的不同[目标实现](https://github.com/p4lang/behavioral-model/blob/main/targets/README.md)有各自的架构和接口。

需要评估目标选择、启动参数、就绪检查和流水线安装，并验证表项、计数器、寄存器及数据包收发。`P4InfoIndex` 和控制器元数据处理也要使用新目标的 P4Info 验证。哪些现有接口可以复用、是否需要改动公开接口，应由集成方案确定。

### 运行时拓扑变更

`Topology` 在 `Network.start()` 之后仍是可修改的描述。向描述中添加主机或链路，不会创建运行资源。`Network` 目前没有在线增删节点或链路的接口。

在线变更需要同步维护拓扑描述、运行节点句柄、命名空间、接口、端口分配和控制面状态，还要处理操作失败时的回滚，以及网络停止时的资源回收。目前的做法是先停止网络、修改描述，再创建并启动新的 `Network`。详见[拓扑变更限制](known-limitations.md#4-不支持运行中拓扑变更)。

### AsyncNetwork

`AsyncP4RuntimeClient` 支持并发 RPC。`await net.astart()` 在工作线程中启动网络，`await net.astop()` 等待网络关闭。同步方法 `Network.start()` 依次启动 BMv2 交换机，等待当前交换机就绪后再启动下一台。

在主线程的事件循环中调用 `astart()`，会在启动前安装信号清理处理器。取消启动时，会等待启动和清理结束后再传播取消异常。关闭完成前，保持异步客户端所属的事件循环运行。详见[异步生命周期指南](async-client.md#关闭网络)。

后续的 `AsyncNetwork` 可以基于这些生命周期方法，提供异步上下文管理器或协调多个网络。这些新增功能可以保留同步生命周期接口。

## 长期搁置

- **分布式实验**：`Network` 在一台 Linux 机器上管理资源。多机编排需要远程资源管理、跨机链路，以及启动和清理过程的协调。
- **Web 界面**：目前提供交互式 CLI 和 Graphviz 拓扑导出。浏览器中的可视化与控制不在上面的候选范围内。
