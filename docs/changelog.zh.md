# 变更日志

## 1.11.0 · 2026-11-23

- 同步客户端的 `set_pipeline_config(action="COMMIT")` 和异步客户端的 `push_pipeline(action="COMMIT")` 可以启用此前通过 `VERIFY_AND_SAVE` 保存的流水线。此时可省略流水线参数。提交后，客户端会从交换机回读 P4Info。
- `RunningSwitch` 提供的同步和异步客户端共用 P4Info 缓存。两类客户端都会在重连时刷新 P4Info，由网络管理的异步客户端在首次连接时也会回读。
- 异步客户端每条连接最多为 `expect_packet_in()` 缓存 256 条 PacketIn 消息。队列满时，新报文仍会交给已注册的处理器。
- 同一客户端上的并发 `connect()` 共用一次连接尝试。连接失败时释放连接资源，断开时唤醒正在等待 PacketIn 的调用。
- `VERIFY` 保留当前 P4Info 索引。使用 P4Info 的操作会检查连接和流水线是否已变更，避免用过期的 P4Info 发出请求或解码响应。
- `stop()` 和 `astop()` 会报告清理失败，后续调用可以重试。一次关闭中，各异步通道共用等待期限。启动失败时，回滚过程保留原始启动异常。
- 修复 veth 端点移入 PID 1 的网络命名空间后的跟踪问题。
- INT 示例改在出队后采集出口队列深度。异步并发示例在配置失败时也会关闭客户端。
- 更新 README 快速上手和异步编程、IPv6、非对称链路及 INT 的中英文示例指南。

### 从 1.10 升级

- 处理关闭未完成时抛出的 `NetworkError`。在 `await net.astop()` 期间保持异步客户端的事件循环运行，重启前重试尚未完成的清理。重启后，从网络重新获取交换机客户端。

## 1.10.1 · 2026-11-21

- 安装包新增 Python 3.14 和 3.15 分类，CI 在 Ubuntu 22.04 和 24.04 上运行这两个版本的默认测试集。
- 更新 P4Net 项目介绍，修订中英文快速上手、CLI 参考和示例教程。
- 说明 Linux 生成 IPv6 链路本地地址的条件，以及多跳 INT 示例如何估算交换机之间的时延。
- 修复异步并发示例中三台主机的 IPv4 连通性。
- 移除性能测试导出结果和已发布数据中的本机绝对路径。

## 1.10.0 · 2026-11-20

- `ping` 和 `ping6` 发送多个探测包时逐条显示应答，结束时汇总发送数、接收数和丢包率。`pingall` 和 `pingall6` 分批显示进度，取消时显示已完成的结果。
- `<host> cmd` 随命令刷新及时显示 stdout 和 stderr。`<switch> packet listen` 逐包显示，监听结束时汇总收到的包数。
- `NetworkNamespace.popen()` 新增 `start_new_session` 参数。`NSProcess.stdout` 和 `NSProcess.stderr` 可访问已捕获的管道。
- 执行交互命令时按 `Ctrl-C` 会取消当前命令并返回提示符，拓扑继续运行。主机命令取消或超时时会清理进程组。终端挂断由默认信号处理机制接管时，会清理拓扑。
- 更新 CPU punt、非对称链路和多跳 INT 示例。多跳 INT 教程补充了隔离命名空间和时间戳文件的并行运行方法，集成测试也改用各自的时间戳文件。
- 明确 BMv2 执行 `counter reset` 时，会按 P4Info 中的计数器单位清零相应字段。

### 从 1.9 升级

- 解析交互输出的脚本应处理新增的进度行、多次 ping 的汇总，以及 `packet listen` 结束时的包数。单次 ping 显示 `OK` 或 `FAIL`。主机命令的 stdout 和 stderr 可能按终端读到的顺序交错出现。
- 要关闭拓扑，在提示符处输入 `exit` 或 `quit`，也可以在空行上按 `Ctrl-D`。

## 1.9.0 · 2026-11-20

- 交互模式提示拓扑开始启动、网络与 `setup()` 就绪，以及开始清理。`packet listen` 在等待前显示交换机、目标包数和超时。
- 新增 `counter <name> --nonzero`，省略包数和字节数均为零的单元。`counter <name>` 和 `counter <name> --all` 都列出交换机返回的全部单元。
- 帮助总览按命令类型分组，长语法按参数组折行。命令输出与下一次提示符之间留一行空白。
- `table dump` 在顶部显示表名和表项数，匹配字段及动作参数按 `名称=值` 逐行显示。
- 通过 GitHub Actions Trusted Publishing 向 PyPI 上传发布文件，并附上签名的来源证明。

## 1.8.2 · 2026-11-19

- 同步 P4Runtime 客户端改用 gRPC 的默认保活策略，修复此前 10 秒保活周期在空闲后可能触发的 BMv2 `too_many_pings` 断连。调用方可通过 `channel_options` 显式设置保活周期。

## 1.8.1 · 2026-11-19

- 安装指南推荐用 pipx 全局安装 CLI，教程和示例统一使用 `sudo p4net`。指南同时说明 Ubuntu 24.04 自带 pipx 的安装方式，以及项目虚拟环境中的用法。
- 对齐 `hosts`、`pingall`、`pingall6` 和交换机计数器的输出列。增加 ping 矩阵的列间距，计数器数值右对齐。
- 交互式帮助和补全支持实际的主机名与交换机名。命令错误统一显示格式。
- BMv2 启动超时时，在清理前保存最近一次监听检查结果、进程状态和线程状态。诊断文件保存成功时，启动异常会显示其路径。
- 文档站点在访问不存在的路径时显示自定义 404 页面，将错误页排除在站内搜索和索引之外，并为语言切换标记生成绝对 URL。

## 1.8.0 · 2026-10-25

新增 `Network.astart()` 和 `Network.astop()`，在事件循环中等待网络启停，并在取消后完成清理。`NSProcess` 新增 `communicate()` 和 `send_signal()`。`VethPair` 新增可选的 `namespace_a`、`namespace_b` 关键字参数，创建接口时即可指定两端的目标命名空间。

CLI 新增 `key=值&&&掩码` 三态匹配和 `key=下界..上界` 范围匹配。`tools/benchmark.py` 可采集启停耗时、CPU、内存和连通性数据。已公布的数据仍为 2026-10-23、提交 `b2ebbc9` 的[历史基线](performance.md#测试环境)。

本次修复包括：

- 编译缓存跟踪包含文件，处理并发写入和不完整产物，强制重编译失败时保留已有可用产物。
- 同步与异步连接在失败、流终止或取消后释放资源。异步主控状态随仲裁响应更新，RPC 异常分类和批量操作错误详情修正。
- 网络启停、信号和取消操作协调清理，异步连接在所属事件循环中关闭。子进程不再沿用父进程的清理登记。启动等待已配置的 IPv6 地址，并按交换机设置抓包。
- BMv2 启动时确认监听端口归属。拓扑提前检查 gRPC/Thrift、CPU/数据端口冲突。
- 保留中文等 Unicode 接口名，按目标命名空间检查重名，跨命名空间复用不受链路顺序影响，销毁后的 veth 对象可重新创建。
- 按实际配置到已连接接口的 IP 判重，忽略前缀长度，排除被覆盖的默认地址和未连接主机。导入快照中的节点映射、端点引用和交换机端点地址也参与校验。
- P4Runtime 匹配检查位宽、规范形式和优先级，涵盖 OPTIONAL 表与删除操作；省略全范围通配字段，拒绝反向范围。
- ping 保留小数超时、限制发包次数，收到至少一次应答即成功。CLI 在执行或登记回调前校验 ping、报文监听参数，修复无选项监听及拓扑模块加载。

中英文安装、快速上手、异步、CLI、架构、故障排查、API 稳定性、性能和发布指南已按实际行为修订。文档中文使用宋体，英文使用 Times New Roman，代码区和 API 签名保留等宽字体。源码包只包含选定的项目文件，文档依赖支持 Python 3.10。

### 从 1.7 升级

- 在事件循环中使用 `await net.astart()`、`await net.astop()`，等待启停和资源回收完成。异步客户端所属的循环应持续运行到关闭完成。同步场景继续使用 `start()`、`stop()`。示例见[异步指南](async-client.md#关闭网络)。
- 地址和网关只传字符串或 `None`，整数字段不接受 `bool`，布尔开关只传 `bool`。导入拓扑快照时为每个端点提供 `port`、`iface_name`，再调用 `validate()`；新建拓扑可由 builder 分配。修正重复节点名和实际接口 IP。非法快照在校验时报 `TopologyError`，导入本身保留端点数据。
- LPM 使用 `10.0.0.0/24`，不要使用带主机位的 `10.0.0.5/24`。TERNARY 使用 `(0xa0, 0xf0)`，不要使用掩码外仍有值位的 `(0xab, 0xf0)`。反向范围和超出位宽的值会在 RPC 前报 `EncodingError`。`/0` 与零掩码保留现有通配行为。
- 含 OPTIONAL、TERNARY 或 RANGE 键的表，插入和删除表项都要提供 `1..2147483647` 的整数优先级，包括通配表项。仅含 EXACT/LPM 键的表省略优先级。语法与示例见 [CLI 参考](cli.md#table-add--match--action--params--priority-)。
- 检查依赖旧 RPC 异常类别的处理代码。权限错误使用 `NotPrimaryError`；异步流水线的 `INVALID_ARGUMENT`、`FAILED_PRECONDITION` 使用 `PipelineError`。取消和超时按操作区分，见[异常说明](async-client.md#错误超时与取消)。
- ping 次数要求正整数，超时要求有限非负数，支持小数，`0` 由整体等待时限保证退出。部分丢包时至少一次应答即成功。BMv2 的启动、就绪等待和停止超时则要求有限正数，不接受 `bool`。
- tc 参数使用数值紧邻单位的 ASCII 格式，例如 `10mbit`、`1.5ms`。将 `1 ms` 改为 `1ms`，空白、非 ASCII 数字或单位会报 `TcError`。`10Mbit`、`1MS` 等 ASCII 单位大小写仍可使用。
